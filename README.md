# CAD-Compiling: a model-evaluation kit for CAD editing tasks

One folder holds everything needed to test a model on CAD editing: tasks, input models, golden answers, deterministic
verifiers, rubrics, a sandboxed agent harness, a notebook and an original task. **The model is the only part you swap**
(`models.json`).

## What is where

| Requested | Where | What it is |
|---|---|---|
| 1. Notebook | [`notebooks/cad_model_eval.ipynb`](notebooks/cad_model_eval.ipynb) (built by [`scripts/build_notebook.py`](scripts/build_notebook.py)) | Self-checks, verifier calibration, replay, live model evaluation with pass@k, a parametric task family, and optional LoRA SFT plus verifier-filtered rejection sampling |
| 2. Verifiers | `tasks/*/verifier/test.py`, run through [`kit/grade_one.py`](kit/grade_one.py) | Deterministic and representation-agnostic: they measure material in the solid (point-in-solid probes, radial scans, volume difference against the golden answer), never the feature tree. Contract: `run_tests(context) -> {score, passed, critical_failed, failed_check_ids, criteria}` |
| 3. Tasks worked on | `tasks/T001`–`T003` | Hydraulic rod-gland re-bore (Ø50→Ø56 rod), NEMA 17 pattern inference on a motor mount, Minarelli P6 gearbox re-ratio (involute re-cut). Each has prompt, rubric, input, renders, golden answer, verifier and recorded model attempts |
| 4. Harness repo | [`kit/`](kit), [`run_eval.py`](run_eval.py), [`models.json`](models.json) | Sandboxed `/workspace`, agent loop (the model runs Python/CadQuery and sees the output), swappable model adapters, verifier, reproducibility re-run, rubric judge, reports |
| 5. Three deliverables | [`tasks/T004_pillow_block_6204_to_6205_retrofit/`](tasks/T004_pillow_block_6204_to_6205_retrofit) | Original task, below |

### The original task (T004): pillow-block retrofit from a 6204 to a 6205 bearing

| Deliverable | File |
|---|---|
| Task prompt | [`prompt.md`](tasks/T004_pillow_block_6204_to_6205_retrofit/prompt.md) |
| Input file | [`files/problem/model.step`](tasks/T004_pillow_block_6204_to_6205_retrofit/files/problem/model.step) (generated by [`authoring/make_input.py`](tasks/T004_pillow_block_6204_to_6205_retrofit/authoring/make_input.py)) |
| Golden reference answer | [`grader-support/gt_solution.step`](tasks/T004_pillow_block_6204_to_6205_retrofit/grader-support/gt_solution.step) (generated by [`gt_solution.py`](tasks/T004_pillow_block_6204_to_6205_retrofit/grader-support/gt_solution.py)) |
| Verifier and rubric | [`verifier/test.py`](tasks/T004_pillow_block_6204_to_6205_retrofit/verifier/test.py), [`rubric.md`](tasks/T004_pillow_block_6204_to_6205_retrofit/rubric.md) |
| Verifier calibration | [`authoring/mutations.py`](tasks/T004_pillow_block_6204_to_6205_retrofit/authoring/mutations.py): 17 plausible wrong answers, each must fail on its intended check |

The model receives a cast-iron pillow block that carries a 6204 bearing and must convert it to a 6205. It has to:
- look up the 6205 dimensions (d25 × D52 × B15) and the DIN 472 groove for a Ø52 bore (d2 = 55.0, m = 2.15);
- derive the shoulder position from the axial stack (2.00 lip + 2.15 groove + 15.00 bearing = Y 19.15);
- open the shaft passage to Ø33, add a 1.0 × 45° lead-in chamfer, and turn the two Ø11 holes into 11 × 23 belt-tension slots;
- leave everything else untouched.

Every requirement is a measured number with a tolerance: Ø52.00 ±0.04 seat, shoulder 19.15 ±0.05, groove Ø55.0 from Y 2.00 to 4.15, slots 11.0 × 23.0 ±0.05, and at most 0.2 % of the volume differing from the reference. Critical failures cap the score at 0.25.

## Task folder contract

```
tasks/<ID>_<slug>/
  task.json               id, title, timeout, renders, recorded attempts
  prompt.md               what the model sees
  rubric.md               numbered criteria, each with "Weight: N" (100 total) for the rubric judge
  files/problem/          model.step and render_*.png, copied into the model's /workspace
  grader-support/         gt_solution.py and gt_solution.step; never shown to the model
  verifier/test.py        run_tests(context)
  attempts/<name>/        recorded outputs for replay (optional)
```

T001–T003 are imported from a CAD_Edit reviewer folder by [`scripts/import_cad_edit.py`](scripts/import_cad_edit.py). The importer:
- strips the export header;
- restores the `solution.step` line that the export had dropped from the outputs list;
- removes prompt lines for renders that are not in the package;
- keeps one copy of byte-identical attempts.


## Running

```bash
python run_eval.py --model golden
```

```bash
python run_eval.py --model noop --no-repro
```

```bash
python run_eval.py --model replay --k 0
```

```bash
python run_eval.py --model claude-opus --tasks T004 --k 3 --judge claude-opus
```

```bash
python tests/test_agent_loop.py T004
```

What each one does:
- `golden`: every golden answer must pass its own verifier (task self-check).
- `noop`: the unchanged input must fail everywhere (checks the verifier is not trivially satisfied).
- `replay`: grades the recorded attempts in `tasks/*/attempts/` (`--k 0` means all of them).
- `claude-opus` (or any key in `models.json`): a live model, k attempts per task, with an optional rubric judge.
- `tests/test_agent_loop.py`: a no-cost test of the agent loop using a scripted stand-in model.

Each run writes `results/<time>_<model>/`, containing per attempt `transcript.json`, `output/`, `verifier.json` and `judge.json`, plus `summary.json` and `summary.md` (pass@1, pass@k, mean verifier score, mean rubric score).

### Swapping the model

Add an entry to `models.json`. Two providers cover most models:
- `anthropic`: Claude through the official SDK, with streaming, adaptive thinking and the renders attached as images.
- `openai_compat`: any OpenAI-compatible endpoint, such as OpenAI, NVIDIA NIM, OpenRouter, vLLM, Ollama or LM Studio. Set `base_url`, `model`, `api_key_env` and `vision`.

Keys are read from environment variables and never stored in the repo. A new provider is one class with a `chat(system, messages, images)` method in [`kit/models.py`](kit/models.py).

### How an attempt runs

1. A fresh temp workspace gets `files/problem/` and an empty `output/`. Golden files are not copied.
2. The model gets the prompt, the file list and the renders. Each reply may contain one Python block. The block runs with a timeout, and the exit code, stdout and stderr come back as the next message. The run ends when the model replies `FINAL`, or after `--max-turns`.
3. Grading:
   - the verifier runs in its own process;
   - `solution.py` is re-run in a second fresh workspace, and its STEP must match the submitted one (`reproducible`);
   - optionally, a judge model scores the rubric, using the verifier's measurements as facts.

Model code runs on the host. For untrusted models, run the kit inside a container or VM.
